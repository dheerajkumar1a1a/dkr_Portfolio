## Situation

As a developer maintaining a technical portfolio, I faced recurring friction: manually converting project notes into formatted MDX files, updating frontmatter, and deploying changes. This repetitive workflow consumed valuable time and introduced inconsistencies across entries.

## Task

Design and implement an end-to-end automated pipeline that accepts raw Markdown input, enriches it with structured metadata, validates content quality, and deploys a production-ready portfolio site—all triggered by a single git push.

## Action

- **Architected a GitHub Actions workflow** that triggers on pushes to `main`, running linting, type-checking, and content validation before deployment
- **Built a Node.js preprocessing script** that parses raw Markdown, extracts YAML frontmatter, auto-generates missing fields (slugs, reading time, SEO tags), and outputs valid MDX
- **Integrated MDX compilation with Next.js 14 App Router**, leveraging `next-mdx-remote` for dynamic content rendering with custom components (callouts, code blocks, project cards)
- **Configured Vercel preview deployments** for every PR, enabling stakeholder review before merging
- **Added content guardrails**: schema validation via Zod, broken link detection, image optimization with `next/image`, and automated sitemap generation
- **Implemented incremental static regeneration (ISR)** for near-instant updates without full rebuilds

## Result

- **Reduced publishing time from ~45 minutes to <3 minutes** per entry (including preview validation)
- **Achieved 100% type-safe content layer**—zero runtime frontmatter errors in production
- **Enabled non-technical contributions**: teammates can now add projects via Markdown files without touching code
- **Improved Core Web Vitals**: LCP < 1.2s, CLS < 0.05 through automated image optimization and font subsetting
- **Pipeline reliability**: 99.2% success rate across 50+ deployments with automated rollback on failure
