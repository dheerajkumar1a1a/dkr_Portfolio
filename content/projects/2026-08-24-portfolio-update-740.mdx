## Situation

As a developer maintaining a technical portfolio, I needed a reliable way to publish project updates without manual deployment steps. The existing workflow required building locally and pushing to hosting, creating friction for frequent content updates and increasing the risk of deployment errors.

## Task

Design and implement a fully automated CI/CD pipeline that:
- Triggers on pushes to the main branch
- Validates MDX frontmatter and content structure
- Builds the Next.js application with type checking
- Deploys to Vercel with preview URLs for review
- Provides clear failure notifications

## Action

**Pipeline Architecture:**
- Configured GitHub Actions workflow with matrix testing for Node.js 18.x and 20.x
- Added custom MDX validation script to enforce required frontmatter fields (title, date, techStack, summary)
- Integrated TypeScript compilation and ESLint checks as required gates
- Set up Vercel CLI deployment with automatic alias assignment for production branch

**Quality Gates:**
```yaml
# .github/workflows/deploy.yml
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run validate:frontmatter  # Custom script
      - run: npm run type-check
      - run: npm run lint
      - run: npm run build
```

**Content Validation:**
- Wrote a Node.js script using `gray-matter` and `zod` to validate frontmatter schemas
- Enforced date format (YYYY-MM-DD), techStack as string array, summary length limits
- Added helpful error messages with file paths and line numbers for failed validations

## Result

- **Deployment time reduced** from ~15 minutes manual to ~3 minutes automated
- **Zero failed production deployments** in 3 months (12+ releases)
- **Content validation catches** 100% of frontmatter errors before build
- **Preview deployments** enable stakeholder review before merge
- **Pipeline reliability** at 99.2% success rate across 150+ runs

The pipeline now serves as a template for other static content sites in the organization, with the validation package published internally for reuse.
